  3. 3

    Learn

    8 minutes

    Use the Reading 3.4 page as the core explanation. As you reread, make a three-column note: what I asked for, what the system would have to assume, and which specification removes the assumption. This habit turns a vague request into a task a system can actually carry out.

    What I asked forThe request as you first wrote it.
    What the system would have to assumeEvery blank a stranger would fill in.
    Which specification removes the assumptionAudience, purpose, context, constraints, format, examples, or verification.

    Mini-protocol: Specify, compile, check

    1. Specify: Name the audience, purpose, context, constraints, format, examples, and verification requirements.
    2. Compile: Read the prompt as a stranger with no memory of your intent. List every assumption that stranger would have to make.
    3. Check: For each assumption, add a specification or accept the default on purpose. Record why.

    Practice itemStrong reasoning looks like
    “Write me a summary.”A summary of what, for whom, and how long? Audience, purpose, and format are missing, so the system will choose all three.
    “Make it good.”“Good” is not a specification. Replace it with constraints the system can follow: length, tone, reading level, what to leave out.
    “The prompt is long, so it must be clear.”Length is not clarity. A long prompt can still omit the audience or the verification requirement. Check the seven elements, not the word count.
