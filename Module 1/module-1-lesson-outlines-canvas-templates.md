# Lesson 1.1 — What Counts as Intelligent Behavior?

**Estimated time:** 45–55 minutes  
**Canvas items:** Lesson Page; card-sort Experience; Guided Practice Quiz; Diagnostic/Independent Application; Notebook assignment.

## Learning objectives

By the end of this lesson, students can:

1. describe at least four behaviors commonly associated with intelligence;
2. distinguish an automated rule-following system from a system that senses, represents, decides, or adapts; and
3. explain why “intelligent” is a useful but contested label.

## Canvas Page: ready-to-build prose outline

### Why this matters

Students encounter systems described as “smart” every day: recommendation feeds, navigation apps, autocorrect, facial recognition, chatbots, game opponents, and thermostats. But “smart” can mean several different things. A system may follow a fixed rule very reliably without adapting. It may detect patterns without understanding why those patterns matter. It may produce language that sounds thoughtful while lacking a human life, intention, or responsibility.

This course begins by separating three questions that are often blended together:

1. **What can a system do?**
2. **How does it do it?**
3. **What, if anything, does it understand?**

Keeping those questions distinct will help you use AI clearly and evaluate its claims honestly.

### By the end of this lesson, you will be able to …

- identify behaviors often associated with intelligence;
- distinguish simple automation from more adaptive or pattern-based systems;
- explain one reason that calling something “intelligent” can be helpful and one reason it can mislead.

### Before you begin (2 minutes)

Write one sentence: **Name something you use that seems “smart.” What does it do that makes you call it smart?** Do not look up a definition yet.

### Experience: Sort the systems (8 minutes)

Use the embedded **“What Is It Doing?” card sort**. Drag each example into one of four categories:

- fixed automation;
- pattern-based AI;
- human judgment;
- uncertain / depends on more information.

The purpose is not to get every label right immediately. The purpose is to notice what information you need before you can classify a system.

| Example | Fixed automation | Pattern-based AI | Human judgment | Uncertain / need more information |
|---|---:|---:|---:|---:|
| A timer turns lights off at 10:00 p.m. |  |  |  |  |
| A map app changes a route after detecting traffic |  |  |  |  |
| A teacher decides whether an excuse for late work is fair |  |  |  |  |
| A photo app groups images that may show the same person |  |  |  |  |
| A calculator adds two numbers |  |  |  |  |
| A chatbot writes an answer to a history question |  |  |  |  |

### Learn, Part 1: Intelligence is a family of abilities

In ordinary speech, we call a person intelligent when that person can do more than repeat a memorized response. Intelligence often includes abilities such as noticing relevant features, remembering information, representing a situation, comparing possibilities, learning from feedback, reasoning about causes, communicating, planning, and adapting when circumstances change.

No single list settles the meaning of intelligence. A brilliant musician, a careful mechanic, a skilled nurse, and a thoughtful historian may display intelligence in different ways. The same is true of machines: one system may recognize images, another may choose moves in a game, and another may predict the next word in a sentence. Those are real capabilities, but they are not automatically the same capability.

### Learn, Part 2: Four useful questions

When evaluating a supposedly intelligent system, begin with four questions:

1. **What does it receive?** These are its inputs: words, pixels, sound, sensor readings, clicks, numbers, or other data.
2. **What does it produce?** These are its outputs: a label, prediction, recommendation, route, response, action, or score.
3. **What process connects input and output?** It may follow a fixed rule, use a learned pattern, search among options, or combine several methods.
4. **What changes over time?** Some systems never change unless a person reprograms them. Others change because they are retrained or because they use new information.

A light on a timer receives the time and follows a fixed rule. A route planner may combine maps, current traffic data, and an optimization method. A human deciding whether to trust a news story also brings background knowledge, values, responsibility, and the ability to ask new questions. These systems should not be treated as identical merely because each produces an output.

### Learn, Part 3: Why labels can help and mislead

Calling a system “intelligent” can be helpful when it directs attention to sophisticated capabilities: learning patterns, planning, using language, or adapting to feedback. But it can mislead when it makes us assume the system has human-like understanding, motives, wisdom, or moral responsibility.

A careful description is more useful than a flattering label. Instead of saying, “The app understands me,” try: “The app uses past clicks and similar users’ behavior to predict what I may select next.” The second statement tells us what the system does and leaves room to ask whether it is accurate, fair, or appropriate.

### Key vocabulary

- **automation:** a system that carries out a process with little or no ongoing human intervention.
- **algorithm:** a defined set of steps used to solve a problem or complete a task.
- **input:** information a system receives.
- **output:** information or action a system produces.
- **adaptation:** a change in behavior based on feedback, data, or changed conditions.
- **intelligent behavior:** behavior that appears to involve abilities such as perceiving, learning, reasoning, planning, communicating, or adapting; the phrase does not settle whether a system understands.

### Check your understanding

Complete **Guided Practice 1.1**. Read the explanation after every answer; the feedback is part of the lesson.

### Build your Field Guide

Choose five candidate systems for your Module 1 Field Guide. List their names and where you encounter them. They may include school, home, entertainment, transportation, shopping, sports, health/fitness, or creative tools. At least one should be a system whose AI label you are not yet sure about.

Next, you will separate terms that people often use interchangeably—AI, machine learning, automation, algorithms, and computer science. Clear vocabulary will make your Field Guide more accurate.

# Lesson 1.2 — AI, Machine Learning, Automation, Algorithms, and Computer Science

**Estimated time:** 45–60 minutes  
**Canvas items:** Lesson Page; classification Experience; Guided Practice Quiz; concept-map Assignment; Field Guide milestone; Notebook.

## Learning objectives

Students can:

1. define AI, machine learning, automation, algorithm, and computer science in student-ready language;
2. explain how the terms overlap without treating them as synonyms; and
3. classify a system using evidence rather than buzzwords.

## Canvas Page: ready-to-build prose outline

### Why this matters

Technology companies, news stories, and advertisements often use the word “AI” as a compliment, a warning, or a shortcut for anything complicated. That makes the term less useful. If every automated tool is AI, the label tells us almost nothing. If only human-like machines count as AI, we overlook systems that already influence daily life.

This lesson gives you a vocabulary map. You will use it throughout the course to describe systems precisely and resist marketing language.

### Before you begin

Which two terms below do you think are closest in meaning? Which one is broadest? Explain your prediction in 2–3 sentences: **AI, machine learning, automation, algorithm, computer science.**

### Experience: Boundary cases (8 minutes)

Complete the embedded **“Which Label Fits?” classification activity**. For each case, choose the best description and read why more than one label may sometimes apply.

**Fallback:** For each case below, write the most accurate label(s) and a one-sentence reason: a calculator, a spam filter, a washing-machine cycle, a social-media recommender, a hand-written recipe, a scientist’s simulation program, and a self-driving prototype.

### Learn, Part 1: The broad field—computer science

**Computer science** is the study of computation: what can be calculated, how information can be represented and processed, how algorithms work, and how software and hardware systems can be designed. Not all computer science is AI. Building a website, encrypting a message, sorting a list, or designing a database may involve computer science without involving AI.

### Learn, Part 2: Algorithms and automation

An **algorithm** is a defined set of steps for solving a problem or carrying out a task. A cooking recipe can be algorithm-like, although computer algorithms are written precisely enough for a machine to execute.

**Automation** occurs when a system carries out a process with little ongoing human intervention. A fixed rule can automate a process: “If it is 10:00 p.m., turn off the lights.” Automation can be simple or sophisticated. It does not require machine learning.

### Learn, Part 3: Artificial intelligence and machine learning

**Artificial intelligence (AI)** is a broad field concerned with creating systems that perform tasks associated with abilities such as perception, language use, learning, reasoning, planning, or decision-making. AI includes several approaches. Some AI systems use hand-written rules. Some search through possibilities. Some learn patterns from data.

**Machine learning (ML)** is a branch of AI in which a system learns patterns from examples or data rather than relying only on rules written in advance. A spam filter may learn from examples of unwanted and wanted messages. A recommendation system may learn statistical patterns from users’ behavior. ML is therefore inside AI, but AI is not limited to ML.

### Learn, Part 4: A map, not a stack of synonyms

A useful mental model is this:

- Computer science is the broadest academic field in this list.
- Algorithms appear throughout computing, including AI.
- Automation describes a kind of process; it can use fixed rules, AI, or neither.
- AI is a field within computer science focused on intelligent-seeming tasks.
- ML is one important approach within AI.

A system can belong to several categories at once. A recommendation system can be software (computer science), use algorithms, automate suggestions, use AI, and use ML. A timer-controlled light uses an algorithm and automation, but generally not ML. The right question is not “Is this really AI?” in the abstract; it is “Which descriptions accurately explain what this system does?”

### Key vocabulary

- **computer science:** study of computation, information, algorithms, and computing systems.
- **algorithm:** defined steps for completing a task or solving a problem.
- **automation:** carrying out a process with little ongoing human intervention.
- **artificial intelligence (AI):** a broad field for systems that perform tasks associated with perception, language, learning, reasoning, planning, or decision-making.
- **machine learning (ML):** an AI approach in which systems learn patterns from data or examples.

### Apply it independently

Create a concept map, diagram, or annotated table that explains how the five terms relate. Your work must include:

- a definition in your own words for each term;
- at least two overlap relationships;
- one example that fits multiple labels; and
- one example that is automation but not ML.

### Build your Field Guide

For your five chosen systems, add a preliminary label set: AI? ML? automation? algorithm? uncertain? For every label, write a 1–2 sentence justification based on observable evidence. You may revise these later.

### AI Lab Notebook

- Which term was easiest to misuse before this lesson?
- Describe one advertisement or headline you have seen that uses “AI” too vaguely.
- AI-use disclosure.

## Interactive specification: “Which Label Fits?”

- 10 boundary cases; multiple labels may be selected.
- Feedback distinguishes “necessary,” “possible,” and “not supported by evidence.”
- Fallback list is embedded in the lesson page.

- Appropriate examples: 2

# Lesson 1.3 — A History of Thinking Machines

**Estimated time:** 50–60 minutes  
**Canvas items:** Lesson Page; timeline Experience; Guided Practice Quiz; source-card Assignment; Field Guide milestone; Notebook.

## Learning objectives

Students can:

1. identify major developments in the history of AI;
2. explain why periods of excitement and disappointment both occurred; and
3. connect a modern AI system to an earlier technical or intellectual development.

## Canvas Page: ready-to-build prose outline

### Why this matters

Today’s AI systems can feel sudden and unprecedented. They are not. They emerge from a long history of questions about logic, language, calculation, machinery, learning, and mind. That history also includes repeated cycles of bold promises, real achievements, disappointment, funding cuts, and renewed progress.

Knowing this history helps you judge contemporary claims. It teaches a durable lesson: a striking demonstration is not the same as a solved human problem.

### Before you begin

Put these in the order you think they appeared: programmable computers, the phrase “artificial intelligence,” expert systems, deep learning breakthroughs, large language models. Then write one question you have about the sequence.

### Experience: Promise, limitation, consequence (10 minutes)

Use the interactive timeline. Open each event card and read three layers: **what people hoped**, **what the system could actually do**, and **what followed**.

**Fallback:** Read the timeline table on the Canvas Page. For each event, write one sentence completing: “This mattered because …”

### Learn, Part 1: Foundations—logic, computation, and questions about mind

Long before electronic computers, philosophers and mathematicians asked whether reasoning could be represented as rules. Formal logic showed that some forms of reasoning could be expressed symbolically. Work by figures such as Ada Lovelace and later Alan Turing clarified that a general-purpose machine could follow instructions to perform many different calculations.

These developments did not prove that machines could think. They made a new question possible: if some reasoning can be represented as steps, which parts of intelligent activity can be mechanized?

### Learn, Part 2: The birth of AI and symbolic approaches

The term **artificial intelligence** was popularized in 1956 at the Dartmouth summer research project. Early researchers often hoped that tasks such as theorem proving, language translation, and game playing would become easy once the right symbolic rules were written.

Symbolic AI represented knowledge using explicit symbols and rules. It achieved real successes in narrow, structured settings. But ordinary language, visual perception, common sense, and the open-ended world proved much harder than early optimism predicted.

### Learn, Part 3: Expert systems and AI winters

In the 1970s and 1980s, **expert systems** used extensive if–then rules drawn from specialists in fields such as medicine, geology, or equipment maintenance. They could be useful within tightly defined domains. Yet they were expensive to build, difficult to update, and brittle when cases fell outside their rules.

When systems failed to meet inflated expectations, investment and enthusiasm declined. Such periods are often called **AI winters**. An AI winter is not proof that all AI is useless; it is a reminder that promises can outrun evidence.

### Learn, Part 4: Data, learning, and deep neural networks

As more digital data and computing power became available, machine-learning methods gained influence. Instead of trying to hand-write every rule, researchers trained systems to find statistical patterns in examples. Improvements in neural-network methods, data, specialized hardware, and engineering produced strong results in image recognition, speech, translation, games, and other tasks.

### Learn, Part 5: Generative AI and current questions

Large language models and other generative systems produce text, images, audio, code, and video by learning patterns from enormous collections of data. Their outputs can be useful and persuasive. They can also be incorrect, biased, untraceable, or inappropriate for a situation.

History gives us a disciplined response to both hype and panic: ask what the system demonstrably does, what conditions it needs, what it fails at, who benefits, and who remains accountable.

### Key vocabulary

- **symbolic AI:** AI that represents knowledge with explicit symbols and rules.
- **expert system:** rule-based software designed to apply specialized knowledge in a narrow domain.
- **AI winter:** period of reduced enthusiasm and investment after AI systems fail to meet expectations.
- **neural network:** a machine-learning model made of connected computational units that can learn patterns from data.
- **generative AI:** AI that produces new content such as text, images, audio, code, or video based on learned patterns.

### Apply it independently

Complete **Timeline Source Card**. Choose one milestone from the lesson. In 200–250 words, explain:

- what problem people hoped it would address;
- what it could actually do at the time;
- one limitation or disappointment; and
- one credible source used to verify your description.

### Build your Field Guide

Select one of your five systems. Add a short “genealogy” note connecting it to an earlier development (for example, rules/expert systems, statistical learning, neural networks, search, or generative models). Do not claim direct descent unless you can support it; explain the conceptual connection.

### AI Lab Notebook

- Identify one historical promise that resembles a claim you hear about AI today.
- What evidence would you want before accepting that claim?
- AI-use disclosure.

# Lesson 1.4 — What Contemporary AI Systems Do

**Estimated time:** 50–60 minutes  
**Canvas items:** Lesson Page; System X-ray Experience; Guided Practice Quiz; Field Guide Assignment; Notebook.

## Learning objectives

Students can:

1. identify common task categories for contemporary AI systems;
2. describe a system in terms of input, output, task, data, and human choices; and
3. distinguish observable capabilities from unsupported marketing claims.

## Canvas Page: ready-to-build prose outline

### Why this matters

“AI” is not one machine or one ability. Contemporary systems perform different tasks: detecting objects in images, transcribing speech, predicting likely choices, generating text, translating languages, recommending content, or controlling physical devices. Understanding a system begins with describing its task precisely.

A useful habit is to perform a **system X-ray**: look beneath the product name and ask what goes in, what comes out, what task is being attempted, what information or training may be involved, and what human choices shape the system.

### Before you begin

Choose one of these: a navigation app, video recommender, phone camera, chatbot, music app, or online store. In one sentence, state what you think it is trying to do for the user.

### Experience: System X-ray (10 minutes)

Use the interactive explorer to inspect four example systems. For each one, select likely inputs, outputs, task type, and human decisions. Read the explanation before proceeding.

**Fallback:** Complete the embedded four-system table. Examples: route planner, photo organizer, music recommender, customer-service chatbot.

### Learn, Part 1: Tasks, not magic

Common AI task categories include:

- **classification:** assigning an item to a category, such as “spam/not spam” or “plant species A/B/C”;
- **prediction:** estimating a likely future value or event, such as travel time or product demand;
- **recommendation:** ranking options a user might prefer;
- **generation:** producing content such as text, image, audio, code, or video;
- **perception:** extracting useful information from images, sound, or sensor data;
- **planning/control:** selecting actions to reach a goal under constraints.

A single application may combine several tasks. A route planner perceives location data, predicts travel time, searches possible routes, and recommends one. Naming the tasks helps us ask better questions about performance and risk.

### Learn, Part 2: Inputs, outputs, and hidden choices

Systems are shaped by more than their visible interface. Inputs may include information you provide directly, information collected by sensors, records created by others, or patterns in past behavior. Outputs may be labels, rankings, suggestions, generated content, or actions.

Human choices appear throughout: people choose the goal, decide what data to collect, label examples, set rules, write instructions, define success, decide who receives the system, and choose how users can appeal or override it. “The algorithm decided” is usually incomplete. A system’s behavior is connected to human design and institutional decisions.

### Learn, Part 3: Capability versus claim

A marketing claim might say, “Our AI knows exactly what you need.” A careful system description might say, “The app ranks products using patterns in past clicks and purchases; it may not reflect a user’s complete needs or interests.”

The careful description is better because it identifies a mechanism, leaves room for error, and avoids pretending the system has certainty or wisdom. Your Field Guide should sound like the second description.

### Key vocabulary

- **classification:** assigning items to categories.
- **prediction:** estimating an unknown or future value from available information.
- **recommendation system:** system that ranks or suggests options based on patterns and criteria.
- **generative system:** system that produces new content from learned patterns and instructions.
- **system X-ray:** a structured description of inputs, outputs, task, likely data/process, human choices, and limitations.

4. task category or categories;
5. likely human design choices;
6. one benefit; and
7. one limitation, risk, or unanswered question.

You may use reputable sources or make clearly labeled inferences from observable behavior. Do not present guesses as facts.

# Lesson 1.5 — Can a Machine Understand? The Chinese Room

**Estimated time:** 55–65 minutes  
**Canvas items:** Experience Page/interactive; Lesson Page; Guided Practice Quiz; private reflection Assignment; Notebook.

## Learning objectives

Students can:

1. distinguish following symbol-manipulation rules from understanding a language;
2. summarize the central thought experiment commonly called the Chinese Room;
3. state one serious objection or alternative interpretation; and
4. make a qualified claim about what fluent AI language output does and does not establish.

## Canvas Page: ready-to-build sequence

> **Build note:** Place the Experience before the explanatory prose in the Canvas Module. Students should complete the simulation and submit their first reflection before opening the full explanation page. The Page below then begins by connecting their experience to the philosophical question.

### Experience Page: You are the message-response service (10–12 minutes)

**Directions:** You will receive messages written in unfamiliar symbols. You do not need to know what the symbols mean. Use the rulebook exactly as written to choose the correct response. Your goal is procedural accuracy, not translation.

**Rulebook sample:**

| If you receive | Return |
|---|---|
| `△ ○` | `□ △` |
| `○ △` | `○ □` |
| `△ △` | `□ ○` |
| `□ ○` | `△ □` |
| `○ □` | `△ ○` |

After five rounds, display: **“Your responses matched the expected pattern. To an outside observer who understands the language, your answers might appear competent.”**

**Private pre-reading reflection (submit before opening the lesson Page):**

1. Did you understand the symbols? Why or why not?
2. What did you know how to do?
3. If someone outside the room received correct responses, what could that person reasonably conclude—and what could they not conclude?

**Fallback:** Use the rulebook table and five input cards in the Page. Students record output symbols manually, then complete the same reflection.

### Why this matters

Modern language models can write fluent essays, translations, summaries, and conversations. Their fluency raises a difficult question: does producing meaningful-seeming language show that a system understands language? Or can a system manipulate patterns so successfully that it *appears* to understand without having understanding in the human sense?

This lesson does not require you to solve the philosophy of mind. It requires you to make distinctions carefully and resist a shortcut: “It sounds intelligent, therefore it understands exactly as a person does.”

### Before you begin

Review your pre-reading reflection. Write one sentence predicting what the lesson’s central question will be.

### Learn, Part 1: The Chinese Room thought experiment

Philosopher John Searle proposed the Chinese Room thought experiment in 1980. Imagine a person who does not know Chinese sitting in a room. The person receives Chinese symbols and follows an extremely detailed rulebook for matching inputs to outputs. The rules are so effective that people outside the room receive answers that look like competent Chinese conversation.

According to Searle, the person in the room does not understand Chinese. The person manipulates symbols according to rules. Searle used this thought experiment to challenge the claim that a computer program, merely by executing the right formal rules, literally understands language.

The point is not that programs are useless. The point is that **producing appropriate outputs and understanding meanings may be different things**.

### Learn, Part 2: Syntax, semantics, and behavior

The thought experiment distinguishes:

- **syntax:** formal rules for arranging or transforming symbols;
- **semantics:** meaning or what symbols are about;
- **behavioral performance:** what an outside observer can see a system do.

A system can follow syntax and produce impressive behavior. The debate asks whether that is enough for semantics—genuine understanding—or whether something more is required.

This distinction matters for AI literacy. A language model can often predict and generate useful text. That capability can be real and valuable. Yet users should not automatically infer that it has firsthand experience, stable beliefs, moral responsibility, or a human-like grasp of truth.

### Learn, Part 3: A serious objection—the systems reply

Critics of Searle often answer that the person alone is not the relevant system. Perhaps the **whole system**—person, rulebook, memory, and symbol-processing arrangement—understands Chinese even if the individual rule-follower does not.

Other critics argue that understanding might arise from the right kind of embodied interaction with the world, learning, or causal connection to objects and actions. Still others question whether human understanding itself is as mysterious or unified as the thought experiment assumes.

You do not need to choose a final winner. A strong answer explains both the original distinction and a serious challenge to it.

### Learn, Part 4: What the argument does and does not show

The Chinese Room does **not** show that AI cannot be useful, cannot generate correct statements, or cannot perform impressive tasks. It does **not** prove that no machine could ever understand anything. It does show why behavior alone may not settle every question about understanding, consciousness, meaning, or moral status.

For practical AI use, the lesson is simple: judge a system by evidence of what it reliably does, while avoiding unwarranted assumptions about inner states. A fluent output should trigger verification and careful use, not automatic trust.

### Key vocabulary

- **thought experiment:** an imagined situation used to test an idea.
- **syntax:** formal rules governing symbols or their arrangement.
- **semantics:** meaning; what symbols, words, or statements are about.
- **behavioral performance:** observable outputs or actions.
- **understanding:** a contested concept involving meaning, comprehension, or grasp; this lesson does not assume one final definition.

# Lesson 1.6 — From Labels to Judgment

**Estimated time:** 50–60 minutes

## Learning objectives

1. distinguish descriptive, evidence-based claims from vague or anthropomorphic AI claims;
2. revise a system description to identify evidence, uncertainty, and limitations; and
3. complete and defend an accurate AI Field Guide entry.

## Canvas Page: ready-to-build prose outline

### Why this matters

The first five lessons have given you tools for thinking clearly: distinguish automation from learning, name tasks precisely, examine inputs and outputs, recognize history and hype, and separate behavior from claims about understanding. The final step is judgment.

Good judgment does not mean refusing to make claims. It means making claims that are proportional to the evidence. A useful AI Field Guide helps a reader see both what a system can do and where confidence should stop.

### Before you begin

Read this claim: **“This AI knows what students need and gives perfect advice.”** Underline or list the words that need evidence. Then rewrite the claim in one more cautious sentence.

### Experience: Annotate the sample entry (10 minutes)

Use the **Field Guide Entry Annotator**. You will see a weak sample entry about a fictional study app. Highlight:

- vague or anthropomorphic language;
- unsupported factual claims;
- missing inputs/outputs;
- missing human choices;
- missing limitations; and
- revisions that would make the entry stronger.

**Fallback:** Use the marked-up text version in the Page. Add comments in Canvas or submit a numbered list.

### Learn, Part 1: Description before evaluation

Start with what can be observed or supported. A strong description identifies the system, its task, inputs, outputs, and likely process. It separates direct evidence from inference.

For example:

> **Weak:** “The app understands students and knows the best way for them to learn.”
>
> **Stronger:** “The app asks students to answer practice questions, records answer patterns, and recommends additional exercises. The available evidence suggests it uses those patterns to rank activities; this does not show that it knows a student’s full needs or circumstances.”

The stronger version is not less useful. It is more useful because a reader can inspect it.

### Learn, Part 2: Four habits of responsible AI description

1. **Name the task.** Say whether the system classifies, predicts, recommends, generates, perceives, or plans.
2. **Name the evidence.** Identify whether your claim comes from direct observation, documentation, credible reporting, or an inference.
3. **Name uncertainty.** Use phrases such as “appears to,” “likely,” “the company states,” or “the available evidence suggests” when you cannot verify a claim directly.
4. **Name limitations and human roles.** Explain one failure mode, risk, or boundary and identify a human decision involved in the system.

### Learn, Part 3: Judgment is not cynicism

Responsible skepticism is not the same as dismissing every technology. An AI system may be genuinely useful for a bounded task. Clear limits make good use more likely. A navigation app can save time even though it does not understand your life. A language model can help generate questions even though it may invent sources. A classifier can help sort images even though it may fail on unfamiliar cases.

The practical question is: **What is this system good for, under what conditions, with what oversight, and with what limits?**

### Key vocabulary

- **anthropomorphism:** describing a nonhuman system as if it had human feelings, intentions, or understanding.
- **evidence-based claim:** a statement supported by observation, documentation, data, or credible sources.
- **inference:** a conclusion drawn from available evidence rather than directly observed fact.
- **limitation:** a condition under which a system may fail, be unreliable, or be inappropriate.
- **human oversight:** a person’s responsibility to monitor, evaluate, approve, or correct a system’s output or action.
